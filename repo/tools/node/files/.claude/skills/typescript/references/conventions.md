# TypeScript conventions

New code is TypeScript with `strict` on. A JavaScript file gets the same rules,
without the type rules, and it is a candidate for a move to TypeScript.

**Errors are values at a boundary and exceptions inside a module.** One place
maps an internal failure to a coded response of the product.

**Config is read one time, at the composition root.** The rest of the code
gets a typed object. A missing value stops the start, and a secret has no
default.

**Telemetry is OTLP.** The product does not import the SDK of a vendor.

**Tests are Vitest**, with v8 coverage at 100% through `include`, in sequence.

**The `@/` alias inside a package, and three tsconfig layers.** The build
checks with `tsconfig.build.json`, emits, then runs `tsc-alias` on `dist/`.

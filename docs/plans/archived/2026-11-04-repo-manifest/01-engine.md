# U1 — Engine: the manifest library and the repo stale rule

- **Read first:** every owned file, top to bottom, before editing.
- **Lazy-load:** `sync-engine/common` and `sync-engine/write` (P02: the header
  test, the log function, the dry-run conventions), `sync-engine/clone`.

## Ruling

From the design rulings of 2026-11-04:

> - Stale rule on both sides: remove each file with the header that this run
>   does not write, then its empty parent folders up to the target root; a
>   file without the header is never removed. One manifest format:
>   `<tool><TAB><path>`, sorted, first line `# Written by bootstrap. Do not
>   edit this file.` (reader skips `#` lines), written only after a clean
>   run. Mac: `~/.cache/sync-engine/macos-generated.tsv`. Repo (user's
>   proposal): `.config/repo-generated.tsv`, committed (moves with the branch;
>   a cache copy breaks with clones, worktrees, other machines). Each
>   submodule has its own. The first repo sync has no manifest and removes
>   nothing; `migrate.md` lists old leftovers. No `git grep` header scan.

> - One header on both sides, the repo form with the new path:
>   `Synced from bootstrap: <side>/tools/<tool>/<path>. Do not edit this
>   file` (path per the layout ruling: repo/tools or macos/tools)
>   - `The next sync replaces it, and a manual change is lost`. During the
>     transition the detection (first 3 lines) also accepts `Synced from
>     bootstrap`, `Synced from repo-config` and `Generated by macos-setup`; a
>     later cleanup (with a `migrate.md` step) drops the old texts. Merge
>     sources carry `Merged by bootstrap: <path>` where the format has
>     comments; the engine does not read it.

D2: "The 16 plans form one linear chain through requires. Most of them edit
sync-engine/repo-sync or sync-engine/setup-sync, and parallel plans conflict
there."

D5: "Nothing. The first sync has no manifest and removes nothing.
docs/sync/migrate.md lists the old leftovers, and the owner deletes them by
hand as before."

D6: "No. The stale removal and the manifest write run only after a run
without a failure, in this order: stale removal, manifest write,
bootstrap_commit. A failed removal is a failure, so the manifest is not
written and the next clean run tries again."

D7: "The manifest is a committed file of the consumer, so the engine does not
trust it. A row without a TAB, with an empty tool or path, with an absolute
path, or with a .. segment is skipped with a log line and never removed. A
listed path that is a symlink, or that has a symlinked folder between the
target root and the file, is not removed (repo-sync never follows a link)."

D8: "A dry run prints would remove <path> for each stale file and would write
.config/repo-generated.tsv when the new content differs from the file. It
writes and removes nothing. A real run writes the manifest only when its
content changes."

D9: "It stays as it is. It is a rule of the branch model and works also
without a manifest. The stale rule replaces only _rs_stale and the removal in
_rs_skip_required."

D10: "One row <tool><TAB><path> for each file of mode generated that the run
writes or finds unchanged, and for each generated conf.d mise file. A seed, a
merge file, a skipped file (an environment that the repo does not use, a
requires or requires_found file that is not present) and a removed merge task
have no row. The path is relative to MISE_PROJECT_ROOT, without .tmpl."

D11: "Every path that this run handled: each generated, seed and merge file
that the run wrote or kept. Only a listed path that the run did not handle is
a candidate for removal."

D12: "The stale rule skips the paths in _RS_SKIP, because _rs_remove already
removes them. A dry run logs one would remove line for each file."

D13: "LF line endings, no trailing blanks, and exactly one LF at the end, so
the pre-commit hooks never rewrite it."

D14: "sync-engine/manifest takes a link mode. repo: a path that is a symlink,
or under a symlinked folder, is never removed (D7). macos: the stale rule
resolves links and removes the real file, then prunes empty parents up to the
target root ($HOME), never past a symlinked folder (the rule of setup-sync),
because on the Mac ~/.config/mise is a link into the dotfiles/ of the owner,
and the mise config of a deselected tool must go."

## Edits

1. **`sync-engine/manifest`** (new, mode 644, a library that the front-ends
   source; no shebang task header). Start with the bootstrap header of a
   non-seed file in shell comment syntax, then a short comment with the usage
   of each function. Use the function prefix and the log function of
   `sync-engine/common`. Source nothing: the front-end sources
   `sync-engine/common` first. It defines:
   - The constant of the first line:
     `# Written by bootstrap. Do not edit this file.`
   - **Read** `<file>`: print each row of `<file>` that is not empty and does
     not start with `#`. A missing file prints nothing and returns 0. A row
     that breaks D7 (no TAB, an empty tool or path, an absolute path, a `..`
     segment) is not printed; log `<file>: line <n> is not <tool><TAB><path> -
     skipped` once for each such row.
   - **Stale** `<link-mode> <old-rows> <handled> <root> <dry-run>`:
     `<link-mode>` is `repo` or `macos` (D14); any other value is a usage
     error, code 2. `<old-rows>` holds one row on each line. `<handled>` holds
     one path on each line: every path that the run handled (D11). For each
     old row whose path is not in `<handled>` (compare the path only, not the
     tool):
     - Mode `repo`: skip it when the path is a symlink or a folder between
       `<root>` and the file is a symlink (log `kept <path> (link)`).
     - Mode `macos`: resolve the links of the path to the real file (port
       `_ss_real` of B, 344-375, read only) and act on the real file.
     - Skip it when the file is not present; skip it when the header test of
       `sync-engine/common` fails (a file without the header, no log line).
     - Else, in a dry run, log `would remove <show>`; in a real run `rm -f`
       it, log `removed    <show>`, then remove each empty parent folder with
       `rmdir`, from the file up, and stop at `<root>`, at a symlinked folder
       or at the first folder that is not empty (both modes). `<show>` is
       the path as `_rs_path` shows it today. A failed `rm` logs
       `cannot remove <show>` and the function returns 1 at the end; the other
       rows still run.
   - **Write** `<file> <rows> <dry-run>`: build the content: the first line,
     then the rows sorted with `LC_ALL=C sort -u`; LF line endings, no
     trailing blanks, exactly one LF at the end (D13). When `<file>` has the
     same
     content, do nothing. In a dry run, log `would write <show>`. Else write a
     temp file in the folder of `<file>` (`mkdir -p` it first), set mode 644,
     and `mv -f` it over `<file>`; log `wrote      <show>`.
2. **`sync-engine/repo-sync`**:
   - Source `sync-engine/manifest` where it sources the other libraries.
   - Add a rows list (for example `_RS_ROWS`, empty at the start of each run).
     Add one `<tool><TAB><path>` row (D10) where `_rs_file_finish` writes a
     generated file or finds it unchanged, also in a dry run. Do not add a row
     for a seed, a merge file, a skipped file or a failed file. The generated
     conf.d files go through the same file loop, so they get their rows
     there.
   - Add a handled list (for example `_RS_HANDLED`): the path of each
     generated, seed and merge file that the run wrote, found unchanged or
     kept, also a kept seed (D11). Add to it the paths of `_RS_SKIP` (the
     merge tasks of the other model), so the stale rule does not log them a
     second time (D12).
   - Remove `_rs_stale` and its call, and remove `_RS_SEEN` and every line
     that only feeds `_rs_stale`.
   - In the requires skip (today `_rs_skip_required`, after P03 the code that
     logs `skip file  <path> (no <file>)`): remove the removal branch. The
     function only logs `skip file  <show> (no <file>)` and returns 0. The
     stale rule removes a listed copy with the header.
   - Keep `_rs_remove` and `_RS_SKIP` (D9) and `_rs_unblock`.
   - At the end of `repo_sync`, after the clone is removed: when the run has
     no failure, read the old rows of
     `${MISE_PROJECT_ROOT}/.config/repo-generated.tsv`,
     run the stale function with link mode `repo`, `_RS_HANDLED` and root
     `$MISE_PROJECT_ROOT`, and on success run
     the write function with `_RS_ROWS`. A failure of either adds
     `stale files` or `.config/repo-generated.tsv` to `failed` with its code,
     and then `bootstrap_commit` is not set. With a failure in the file loop,
     run neither (D6).
   - Update the header comment of the script: the contract lines about stale
     files and about the requires removal now describe the manifest. Keep it
     short; P15 rewrites the headers.

## Guardrails

- Do not touch `.config/mise/tasks/test/repo-sync`; U2 owns it.
- Do not change the removal of the merge tasks of the other model (D9).
- Never follow a symlink, and never remove a file without the header.
- Write shell for bash 3.2 and bash 5.x: no namerefs, no `${var,,}`, no
  associative arrays. Under `set -e`, write a command substitution that can
  fail as `VAR=$(cmd) || VAR=''`.
- System commands (`git`, `awk`, `sed`, `sort`, `rm`, `rmdir`) get no
  `mise x --` prefix; a tool call that mise installs does.
- Delete with `rm`, never `git rm`.

## Goal

After this plan lands, the `kotlin`, `swift` and `android` tools of bootstrap
ship the generic tasks that the `virajp/claude-plugins` stackgen packs ship
today: the Gradle deps task, the SwiftPM and Xcode deps task, the Android SDK
package install and the Android lint task. The open rulings G1, G7, G8 and K of
the claude-plugins plans are closed in bootstrap, and no mobile tool setup has
to stay in stackgen. This plan finishes backlog item B03.

This is plan 2 of 2 for B03. It requires plan 1,
`docs/plans/2026-10-19-android-swift-java-tools`, which adds the `java`,
`android` and `swift` tools and `docs/sync/vwf.md`. No standing decision is
reversed: the SDK-level and G7 rulings of the user (2026-10-18, 2026-10-19)
are applied as they are.

## Unit contract

Every unit prompt carries, in order: its ruling quoted from this file, its owned
paths plus "touch nothing outside this list", the facts section, the shared-file
rule, and the return block below. A unit never bumps a version, never runs a
generator, never edits a doc outside its Owns, never adds a dependency this file
does not list, never commits. A unit deletes with plain `rm`, never `git rm` —
it stages nothing. A unit never writes a lock file.

A unit returns exactly this block and nothing else — no file contents, no diff:

    CHANGED: <path> — <one line>            (one per file)
    DECIDED: <what> — <why>                 (choices made inside scope, or none)
    DOCS FALSIFIED: <path> — <passage>      (reported, never edited; or none)
    GAP: <what the plan left unspecified and the assumption taken>   (or none)
    UNRESOLVED: <the ruling needed>         (or none)

## Gaps surfaced during execution

- G1 (resolved 2026-10-20 in U3 round 2): E5 does not say which image level
  `setup:deps:android` uses when no `targetSdk` is found. The task now fails
  and names `EMULATOR_IMAGE`, as the compileSdk detect does.
- G2 (open, non-blocking, U3): `03-android.md` asks for a Flutter
  `flutter.compileSdkVersion` example in "Adapt to the repository", but by E2
  `setup:deps:android` never applies to a Flutter app (no root `./gradlew`).
  Assumption: the doc uses a version-catalog example instead.
- G3 (open, non-blocking, U3): `code:lint:android` makes the Gradle path from
  the folder path (`app/feature` → `:app:feature`). A build whose
  `settings.gradle.kts` sets another `projectDir` gets a wrong path. The plan
  does not cover this case.
- G4 (open, non-blocking, U3): E5 spells the package ids with `;`
  (`platforms;android-<lvl>`, `system-images;android-<target>;google_apis`).
  The `android` CLI of the `android-sdk` tool, which E5 names for the install,
  lists packages only in the `/` form. The task uses the `/` form and converts
  a `;` in `EMULATOR_IMAGE`.
- G5 (open, non-blocking, U3): E6 maps a file to the nearest folder with a
  build file. For a file under `buildSrc/`, that gives `:buildSrc:lint`, which
  fails because `buildSrc` is not a project of the build. The task lints every
  module for a `buildSrc/` file.
- G6 (open, U4 round 1): E3 assumes that `--write-locks` writes a lockfile
  for every project. A project without `dependencyLocking` gets none, and the
  plan does not say whether such a project must fail. The U6 scratch gate does
  not test this case.
- G7 (open, non-blocking, U4 round 1): E5 does not say whether the platform id
  must be
  checked against the package list. An unknown platform id installs nothing
  and `android sdk install` exits 0.
- G8 (open, non-blocking, U4 round 1, U3): E6 leaves three cases open: a
  module with no `lint` task, the scope of a Flutter `android/` build (plugin
  subprojects), and an Android Gradle plugin check for applicability. The first
  two are departures from E6's literal text, made because the literal form
  fails at runtime or lints code that the user does not own: the task runs
  `:bootstrapLint` from a temporary init script, which depends on `lint` or
  `lintFix` only in each listed module that has that task, and "every module"
  means the projects below the Gradle root. No plugin check was added (new
  scope); a pure-JVM build now exits 0 but still starts Gradle.
- G9 (open, non-blocking, U4 round 1, U2): E4 does not cover a SwiftPM-only
  root on a host with only the Command Line Tools, or a root `*.xcworkspace`.
  Assumption: the task requires a selected Xcode for every Swift root and
  resolves through `-project` only; `docs/sync/swift.md` says that a root
  workspace is not read. U2 returned this as `UNRESOLVED:`; the orchestrator
  recorded it as non-blocking, because the task works as E4 states.
- G10 (open, non-blocking, convergence guard, U4): the review loop of U4 did
  not settle. Round 1 had 10 findings, round 2 had 10, so the guard ended the
  loop after round 2. The contract is not the suspect; examine the loop first.
  Contested residuals, round 2: (U3, medium) the AGP and SDK-level detect of
  `setup:deps:android` walks gitignored `.worktrees/`, `.claude/worktrees/` and
  `node_modules`, so the main checkout can take its level from another
  checkout; (U3, medium) after an earlier run installed the `_ps16k` image,

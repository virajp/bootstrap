## Ruling

From index.md, assumed decisions:

> E1 — One task `setup:deps:<tool>` per tool, with a `--upgrade` flag, as
> `setup:deps:flutter`. A normal run installs only what the lockfiles name. No
> audit step: `code:sec` runs osv-scanner and grype over the repository.

> E2 — `setup:deps:*` acts on the repository root only (`./gradlew`,
> `Package.swift`, one `*.xcodeproj`). In a Flutter repository,
> `setup:deps:flutter` keeps the `android/` and `ios/` deps, so nothing runs
> twice.

> E3 — Applies when the root has an executable `./gradlew`; else it prints
> nothing and exits 0. A normal run fails when
> `gradle/wrapper/gradle-wrapper.properties` has no 64-hex
> `distributionSha256Sum`. It resolves every resolvable configuration of every
> project (a temporary init script, as stackgen's `stackgenResolveAll`) with
> `--write-locks`, then fails when any `gradle.lockfile` or
> `settings-gradle.lockfile` is new or changed against git — a new module
> without a committed lockfile fails, so the check does not depend on
> `LockMode.STRICT` — and restores every lockfile it changed and removes every
> lockfile it created before it exits. `--upgrade` runs the same resolve with
> `--write-locks --refresh-dependencies`, keeps the new lockfiles, and prints
> `./gradlew dependencyUpdates` when the ben-manes plugin is applied (a missing
> task is a skip, not an error).

> E10 — Each task unit owns its `docs/sync/<tool>.md` (the "Tasks" table and
> "What the tool ships"), as D12 of plan 1. Tool calls go through `mise x --`;
> host commands (`git`, `awk`, `sed`, `find`, `uname`, `swift`, `xcodebuild`)
> do not.

## Edits

1. **`tools/kotlin/.config/mise/tasks/setup/deps/kotlin`** (new, `755`):
   - shebang `#!/usr/bin/env bash`, then the bootstrap header
     (`# Synced from bootstrap:
     tools/kotlin/.config/mise/tasks/setup/deps/kotlin. Do not edit this file.`
     and `# The next sync replaces it, and a manual change is lost.`), then
     `#MISE description="…"`, `#MISE hide=true` if the flutter task has it,
     and `#USAGE flag "--upgrade" help="…"` in the flutter task's style;
   - `set -euo pipefail`, source
     `${MISE_PROJECT_ROOT}/.config/mise/tasks/_scripts/helpers`,
     `cd "${MISE_PROJECT_ROOT}"`;
   - not applicable (no executable `./gradlew`) → exit 0, no output;
   - `print_header` once ("Installing the Gradle dependencies ..." or, with
     `--upgrade`, "Upgrading the Gradle dependencies ..."), then a
     `print_subheader` per step;
   - the checksum check (normal run and `--upgrade`): `print_error` and exit 1
     when `distributionSha256Sum` is missing or not 64 hex digits;
   - the init script: written to a `mktemp` file removed by a `trap`; it
     registers one task in `allprojects` that resolves every configuration
     with `canBeResolved`; name it `bootstrapResolveAll`;
   - Gradle runs as `./gradlew` (the wrapper is the project's own binary, not
     a mise tool), with `--no-daemon` only if the flutter task or the stackgen
     task uses it — otherwise the default;
   - normal run: record the lockfiles that git tracks and their state; run the
     resolve with `--write-locks`; compare with git
     (`git status --porcelain -- '*gradle.lockfile' 'settings-gradle.lockfile'`
     and the untracked ones); restore changed tracked lockfiles
     (`git checkout -- <file>` or `git restore`), remove created untracked
     lockfiles with `rm`; when anything was new or changed, `print_error` with
     the list and the fix ("run `mise run setup:deps:kotlin --upgrade` and
     commit the lockfiles") and exit 1. Do the restore in a `trap` too, so an
     interrupted run leaves the tree clean;
   - `--upgrade`: run the resolve with `--write-locks --refresh-dependencies`,
     keep the files, then `./gradlew dependencyUpdates` when the task exists
     (detect "Task 'dependencyUpdates' not found" or check
     `./gradlew tasks --all` output; a missing task is a `print_info` skip);
   - bash 3.2 and 5.x safe; `VAR=$(cmd) || VAR=''` under `set -e`.
2. **`docs/sync/kotlin.md`**: "What the tool ships" gets the row for
   `.config/mise/tasks/setup/deps/kotlin` (Synced, the task
   `setup:deps:kotlin`); "Tasks" gets the task with one line per behaviour
   (root `./gradlew` only, checksum check, lock check, `--upgrade`); "When the
   tool is relevant" and "Adapt to the repository" mention that the task
   needs committed lockfiles (`dependencyLocking`) and a
   `distributionSha256Sum`, and that the Android part of a Flutter app is
   handled by `setup:deps:flutter`.

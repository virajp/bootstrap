## Ruling

From the design rulings of 2026-11-04, verbatim:

> - Seeds on both sides use the setup-sync form: `[files."<target>"]` (target
>   path, no `.tmpl`), `mode = "seed"`, `requires = [...]` (exact paths
>   relative to the target root, each must exist). `seed = [...]` and
>   `[seed_requires]` go (exit 2 naming the new key). No `[files]` table =
>   `mode = "generated"`. The repo mise-entry `requires` (a file name searched
>   4 folders deep) is a second meaning of the word: solve it in the "mise
>   config" row.

> - Merge mode (`mode = "merge"`, JSON/YAML/TOML, `remove`, `remove_items`)
>   moves into the shared engine and is available to repo tools. No repo
>   tool uses it until a real need (candidates: `.vscode/settings.json`,
>   `.claude/settings.json`). Repo side order: merge, dprint format, compare.
>   `[overrides.gitignore]` stays as it is. Merge mode = tool author declares
>   enforced keys; overrides = consumer changes defaults; two mechanisms. The
>   three override shapes (`[overrides.gitignore]`, `[overrides.mise*]`, Mac
>   `[overrides.<tool>]`) get aligned in the "Values" row.

> - One header on both sides, the repo form with the new path:
>   `Synced from bootstrap: <side>/tools/<tool>/<path>. Do not edit this
>   file` (path per the layout ruling: repo/tools or macos/tools)
>   - `The next sync replaces it, and a manual change is lost`. During the
>     transition the detection (first 3 lines) also accepts `Synced from
>     bootstrap`, `Synced from repo-config` and `Generated by macos-setup`; a
>     later cleanup (with a `migrate.md` step) drops the old texts. Merge
>     sources carry `Merged by bootstrap: <path>` where the format has
>     comments; the engine does not read it.

> - mise config: both sides generate `conf.d/<tool>/mise.<env>.toml` from
>   `[mise.*]` and `[mise_env.<env>.*]` of `tools.toml`; no tool ships a mise
>   fragment. Context7 (release notes 2026.9.14): global `conf.d` folder
>   fragments load `mise.toml` and `mise.<env>.toml`. Valid sections get
>   `[bootstrap.*]` and `[dotfiles]` on both sides. The 83 plain Mac
>   fragments move into `tools.toml`; the 6 templated ones (claude-cli, cli,
>   devtools, fish, macos-defaults, network: packages, aliases, PROJECTS_DIR,
>   dock position, login shell) stay open until the "Values" row.

> - Values row, item 3: the shared `tools.toml` schema accepts `[defaults]`,
>   `[questions]` (`question`, `detect`, `example`; the guide asks, the
>   engine only validates) and `[contributes.<tool>]` on both sides. Merge
>   order: defaults, then contributions, then `[tools.<name>]`. The repo side
>   moves none of its existing top-level keys (`commit_scopes`, `extensions`,
>   `[claude.plugins.*]`, `[branch.*]`); a new repo tool value goes into
>   `[tools.<name>]`. Repo questions stay in `docs/sync/tools/<tool>.md`; a
>   new repo tool may use `[questions]`. `[[precommit]]` is a special-name
>   contribution; a later move to `[contributes]` is possible.

> - Values row, item 5 (values into generated mise config):
>   1. Map values (packages, aliases, `[env]`, defaults domains) move directly
>      into `[mise.*]` of `tools.toml` (`[defaults.packages]` →
>      `[mise.bootstrap.packages]`); changed with `[overrides.mise.*]`.
>   2. User additions go into `[mise.*]` of `macos.toml`; the engine generates
>      `~/.config/mise/conf.d/zz-macos/mise.toml` (loads last, wins; the Mac
>      twin of `zz-repo`). "An override cannot add a key" stays (else a new
>      alias lands in all 12 tools with `[shell_alias]`).
>   3. The engine renders the generated mise file with gomplate and the
>      tool's values, so a `[mise.*]` string can hold `<% %>` (e.g.
>      `PROJECTS_DIR = "<% .config.projects_dir %>"`); `required` and
>      `test.Fail` checks keep working.
>   4. A conditional section (fish `login_shell` bool) becomes a value:
>      `[mise.bootstrap.user] login_shell = "<% .config.login_shell %>"`.
>      All 6 templated Mac fragments become `tools.toml` tables.

Note: item 3 above is superseded by P08 D6. The engine renders a `tools.toml`
that holds `<%` before it generates, so the generated file holds the rendered
value. A `<% %>` expression sits inside a TOML basic string ("..."), and each
string literal inside the expression is a Go raw string in backticks.

> - Phases: `stage` is in the shared `tools.toml` schema; only the Mac
>   front-end reads it (init stage today: bash, fish, zsh); a repo tool with
>   `stage` → exit 2. Exit 4 stays Mac-only; shared exit codes 2, 3, 5.
>   Environments (which config mise loads) and stages (sync order) stay
>   separate ideas.

> - Import (user, 2026-11-04): no history, no copy. Read `macos-setup/tools/`
>   and write `bootstrap/macos/tools/` directly in the new format. Verify the
>   result against `macos-setup/dotfiles/`, which is the live model.
>   Comparison: (1) render into a scratch `HOME` with `--no-bootstrap` and a
>   test `macos.toml` with the real selection and answers; (2) plain files
>   outside `.config/mise/conf.d/`: byte compare after header removal; (3)
>   mise config: merge all `conf.d` files of each model, compare section by
>   section (`[tools]`, `[bootstrap.*]`, `[shell_alias]`, `[env]`,
>   `[dotfiles]`, `[settings]`); (4) each difference is a bug or an intended
>   change, listed for the user's approval before the first real run; (5)
>   identity files with the real answers (live renders come from `[vars]` of
>   `identity.toml`). The real-Mac `--dry-run` stays the last check.

Plan decisions:

D1: "The path of the login shell, default /opt/homebrew/bin/fish in
[defaults]. [mise.bootstrap.user] login_shell = "<% index .config
`login_shell` | required `fish: set login_shell in [tools.fish] of
macos.toml` %>". A user who wants another login shell writes its path in
[tools.fish]. The old bool and its conditional section go."

D2: "The expression sits inside a TOML basic string ("..."), and each string
literal inside it is a Go raw string in backticks, never a double quote, so
the TOML string needs no escape. The engine renders a tools.toml that holds <%
before it generates (P08 D6), so the generated mise file holds the rendered
value."

D3: "Inside the <% %> expression of
[mise.bootstrap.macos.defaults."com.apple.dock"] orientation: required with
the message `macos-defaults: set dock_orientation in [tools.macos-defaults] of
macos.toml`, then test.Fail when the value is not bottom, left or right, then
the value. Each other domain of the old [defaults.domains] becomes
[mise.bootstrap.macos.defaults."<domain>"] with the same keys."

D4: "Each shipped file keeps its content byte for byte. Only the old header
line becomes the new two-line header, and each required message that named
<tool>.toml now names [tools.<tool>] of macos.toml. Each old
`.config/mise/conf.d/*` fragment is not shipped: its tables move into [mise.*]
of tools.toml."

D5: "It goes. A tools.toml has [defaults] only when it holds a value."

D6: "Its first line `# Merged by macos-setup:
tools/gh/.config/gh/config.yml.tmpl`
becomes `# Merged by bootstrap: macos/tools/gh/.config/gh/config.yml.tmpl`. It
gets no sync header, because a merge target carries no header and the engine
does not read this line."

D9: "No. The 16 plans form one linear chain through requires, because most of
them edit sync-engine/repo-sync or sync-engine/setup-sync, and parallel plans
conflict there."

D11: "The three [files] tables with mode = "seed" stay as they are. The three
seed files are copied byte for byte with no header, because a seed has no
header."

D12: "The exception of P11 D4. A comment that names an old values file of the
config folder (gh.toml, git.toml, ssh.toml) now names [tools.<name>] of
macos.toml: gh config.yml.tmpl:7, git config.tmpl:3, git identity.tmpl:3 and
ssh config.identity.tmpl:3. The unit reports each such edit as DECIDED. No
other comment changes (D4)."

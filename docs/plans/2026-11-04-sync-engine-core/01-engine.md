## Ruling

From the design rulings of 2026-11-04:

> - The engine starts gomplate, jq and yq as `mise x <tool>@latest --` from
>   `/`: no pins (drop setup-sync's gomplate@5.3.1, jq@1.8.2, yq@4.54.1), no
>   `#MISE tools.gomplate` directive for the engine. Works before a first sync,
>   on a new Mac, in test scratch folders. The template data stays per
>   front-end; only the delimiters and the gomplate call are shared.

> - One header on both sides, the repo form with the new path:
>   `Synced from bootstrap: tools/<side>/<tool>/<path>. Do not edit this file`
>   - `The next sync replaces it, and a manual change is lost`. During the
>     transition the detection (first 3 lines) also accepts `Synced from
>     bootstrap`, `Synced from repo-config` and `Generated by macos-setup`; a
>     later cleanup (with a `migrate.md` step) drops the old texts. Merge
>     sources carry `Merged by bootstrap: <path>` where the format has
>     comments; the engine does not read it.

> - Formatter: the parse check (jq for JSON, yq for YAML/TOML; a target that
>   does not parse → exit 2, old file stays) moves into the shared engine and
>   runs on both sides. The `format` key (`text`/`json`/`yaml`/`toml`,
>   default from the extension) is in the shared `[files]` schema. dprint
>   stays repo-only; repo order: render, parse check, merge, dprint,
>   compare. The Mac does not format.

From this plan:

D5: "_se_log prints '<prefix>: <text>' on stderr, with the prefix in the
variable _SE_PREFIX. sync-engine/repo-sync sets _SE_PREFIX=repo-sync before

[mise.tools.gomplate] table of tools/repo-sync/tools.toml stays. The #MISE

D8: "Every path that the engine gives to gomplate, jq or yq is absolute.
repo_sync makes the path of the values file absolute at its start; each other

temp folder."

every file that the sync writes or compares: a template render, a plain copy,

D10: "Every place that reads the bootstrap header today: the unblock of a

## Edits

Each new library has mode 755 (D19), starts with `#!/usr/bin/env bash` and
a comment of at most 10 lines (what it holds, that a front-end sources it, the
functions it
gives). No bootstrap header (D14 of plan 1). Names: `_se_` for functions,
`_SE_` for globals.

1. **`sync-engine/common`** (new)
   - `_SE_PREFIX` (default `sync-engine`) and `_se_log <text...>` (D5).
   - `_se_mode <path>`: A's `_rs_mode` (GNU `stat -c`, else BSD `stat -f`).
   - `_se_path <path>`: A's `_rs_path`.
   - `_SE_TMPS=()`, `_se_cleanup` and the three traps, as A:219-228 set them
     when sourced.
   - `_SE_HEADER_RE='(Synced from (bootstrap|repo-config): |Generated by
     macos-setup)'`
     and `_se_has_header <file>`: a regular file whose first 3 lines match
     the regex (D10).
   - `_SE_HEADER_LINE1='Synced from bootstrap: %s. Do not edit this file.'`
     and `_SE_HEADER_LINE2='The next sync replaces it, and a manual change is
     lost.'`
     (printf formats; a front-end adds its comment marker and the path).
   - `_se_record_commit <file> <key> <commit> <dry_run> <comment> [<header>]`:
     A's `_rs_record_commit` with the key and the comment line as parameters
     (the same awk). It resolves a symlink and writes the real file, so the
     link stays. A file that is not there: with `<header>`, create it with the
     header lines and the key; without, log `cannot write <file>` and return
     1 (D17). The messages keep the form
     `would set <key> <commit> in <file>` and `set <key> <commit> in <file>`.
   - `_se_gomplate <args>`: `(cd / && mise x gomplate@latest -- gomplate
     --left-delim '<%' --right-delim '%>' "$@")`.
     `_se_jq <args>`: `(cd / && mise x jq@latest -- jq "$@")`. `_se_yq
     <args>`: `(cd / && mise x yq@latest -- yq "$@")`. Standard input
     passes through. Before you write them, check with Context7 (mise) how
     `mise x <tool>@latest --` resolves `latest`. If it can fetch, each
     wrapper sets `MISE_OFFLINE=1` when `mise ls --installed <tool>` lists a
     version (D14). Report what you find as a `DECIDED:` line.
2. **`sync-engine/write`** (new)
   - `_se_format <target> <file> [<format>]`: prints `json`, `yaml`, `toml`
     or `text`. A given `<format>` wins. Else from the extension of
     `<target>`: `.json` → `json` (but `text` under D6, from the lines of
     `<file>`), `.yaml`/`.yml` → `yaml`, `.toml` → `toml`, else `text`. The
     `.tmpl` suffix is not part of the target.
   - `_se_parse_check <file> <format> <show>`: `json` → `_se_jq empty <file>`,
     and an empty or whitespace-only file fails; `yaml` and `toml` →
     `_se_yq -p <format> -o json '.' <file>` (as B:1229); `text` → 0. On
     success, discard the stdout and the stderr of the tool (D15). A failure
     prints the message of D9 with `<show>` through `_se_log`, then the tool
     output on stderr, indented by two spaces, and returns 2.
   - `_se_tmp <dir>`: `mktemp "<dir>/.sync-engine.XXXXXX"`, added to
     `_SE_TMPS`; prints the path.
   - `_se_seed_kept <dest>`: 0 when `<dest>` exists (the caller logs
     `kept seed`).
   - `_se_unblock <dir> <root> <dry_run>`: A's `_rs_unblock` with the root as
     a parameter and `_se_has_header` (keep its messages).
   - `_se_finish <mode> <tmp> <dest> <show> <dry_run>`: the tail of A's
     `_rs_file_finish` (A:1673-1708): compare, `unchanged`, `would chmod`,
     `chmod`, `would update` with `diff -u` and its labels, `chmod`, `mv`,
     `updated`. Keep each message byte for byte. The labels stay
     `(current)` and `(bootstrap)`.
3. **`sync-engine/select`** (new)
   - `_se_pack` and `_se_selected <packs-file> <tools-dir> <base> <sel>
     <shown>`:
     A's `_rs_pack` and `_rs_selected` with these parameters in place of the
     fixed `tools/packs.toml`, `$dir/tools` and `_RS_BASE_PACK`. `<shown>`
     is the name of the packs file in each message (repo: `tools/packs.toml`).
     Keep each message.
   - `_se_walk <deps-callback> <done-callback> <start-tools>`: the
     depth-first walk of `_rs_resolve` (A:619-660), with its state in
     `select` (D11): `_SE_WALK_VISITED` (the finished tools, in the order of
     today, a dependency before the tool that named it) and the deps of each
     tool. `<deps-callback> <tool>` prints the dependency names of `<tool>`,
     or returns 2 or 3 after its message. `<done-callback> <tool>` runs when
     the walk finishes `<tool>`, at the point where today's loop reads the
     other fields, and can return 2 after its message. `_se_walk` returns
     the first code that is not 0.
4. **`sync-engine/repo-sync`**
   - After the shebang comment: source `common`, `write` and `select` from
     the folder of this file (`${BASH_SOURCE[0]%/*}`), then set
     `_SE_PREFIX=repo-sync`.
   - Remove `_rs_log`, `_rs_mode`, `_rs_path`, `_rs_cleanup`, the traps,
     `_RS_TMPS`, `_rs_gomplate`, `_rs_pack`, `_rs_selected`, `_rs_unblock`,
     `_rs_record_commit` and the walk of `_rs_resolve`. Change each call to
     the `_se_` function (D12). `_rs_record_commit` calls become
     `_se_record_commit "$values" bootstrap_commit "$commit" "$dry_run" "# The
     bootstrap commit of the last sync. repo-sync writes it."`.
   - `_rs_resolve` calls `_se_walk` with two repo callbacks: the deps
     callback holds the unknown-tool check (code 3), the manifest read and
     the mise-owner check (code 2); the done callback holds the field loop
     of today (`default_env`, `extension`, `seed`, `seed_requires`, `mise`,
     `mise_requires`, `mise_files`, `root_only`) and adds the tool to
     `_RS_TOOLS`. Each code and message comes in the order of today (D11).
     After the walk, read `_SE_WALK_VISITED` where the code needs the visit
     order.
   - The three header regexes (A:907, A:1417, A:1497) become
     `_se_has_header` (D10). The generated mise header (A:1346) uses
     `_SE_HEADER_LINE1` and `_SE_HEADER_LINE2`; its text stays the same.
   - `_rs_file`: create the temp file with `_se_tmp` and use
     `_se_seed_kept` for the seed gate (D16). After the render or the copy, and
     after the pre-commit
     autoupdate, call `_se_parse_check` with the format of
     `_se_format "$out" "$tmp"` (D9). On code 2, remove the temp file, log
     `kept existing <show>` when the target exists, and return 2.
   - `_rs_file_finish`: keep the `[overrides.gitignore]` part, then call
     `_se_finish`.
   - `repo_sync`: replace the gomplate check with the `command -v mise` check
     of D7 (message: `mise is not available - install it from
     https://mise.run`).
     Make the values path absolute (D8).
   - The header comment: replace the gomplate paragraph (the calling task
     gives gomplate with a `#MISE` line) with the facts of the wrappers and
     D7; add the parse check to "Failure handling" and to code 2.
5. **`tools/repo-sync/.config/mise/tasks/setup/configs/sync`** — remove the
   line `#MISE tools.gomplate="latest"`. Keep `#MISE tools.pre-commit="latest"`.

## Guardrails

- Do not touch the test task; U2 owns it.
- Do not touch `sync-engine/clone`, the forwarding file or the gate.
- Do not change a rule, a message, a code or an order of the sync other than
  the parse check, the gomplate check and the 3-line stale header read.
- Write shell for bash 3.2 and bash 5.x: no namerefs, no `${var,,}`, no
  associative arrays. Under `set -e`, write a command substitution that can
  fail as `VAR=$(cmd) || VAR=''`.
- `mise`, `git`, `awk`, `sed` take no `mise x --` prefix. gomplate, jq and
  yq run only through the three wrappers.
- Delete with `rm`, never `git rm`.

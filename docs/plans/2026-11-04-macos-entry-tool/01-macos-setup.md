## Ruling

From the design rulings of 2026-11-04, verbatim:

> - One shared cache for repos and the Mac: the clone in a `repo/` subfolder,
>   the lock and `macos-generated.tsv` next to it. Origin compare is
>   normalized (repos use SSH, the Mac uses HTTPS). Branch `main` explicit. A
>   non-git, non-empty clone folder stops with exit 2 (no delete). A dry run
>   releases the lock early.

> - Engine variables: `SYNC_ENGINE_CLONE` (temp copy, stub → child task),
>   `SYNC_ENGINE_URL`, `SYNC_ENGINE_CACHE`. Internal only, not user config:
>   test:repo-sync and test:setup-sync use them (today `REPO_SYNC_URL` 8x,
>   `MACOS_SETUP_REPO_URL` 5x, `MACOS_SETUP_REPO_PATH` 3x), and
>   `SYNC_ENGINE_URL`
>   tests an unpushed change. The user saw no value in them and let me keep
>   them on this reason. The forwarding file at the old repo-sync path accepts
>   `REPO_SYNC_CLONE` during the transition.

> - No local engine copy in a consumer. `setup:configs:sync` without
>   `SYNC_ENGINE_CLONE` stops with exit 2. The gate `code:lint:repo-sync`
>   sources the engine from `~/.cache/sync-engine/repo/`; no cache → silent
>   exit 0, never a clone.

> - The `.tmpl` suffix stays the only template marker; no `template = true`
>   key. **Why:** without the suffix, bootstrap's check-json/toml/yaml hooks,
>   dprint (global config excludes `**/*.tmpl` from shell) and mise (cd into
>   `tools/mise/`) read template sources as real files. The engine finds
>   `<target>` or `<target>.tmpl`; both → exit 2.

> - One header on both sides, the repo form with the new path:
>   `Synced from bootstrap: <side>/tools/<tool>/<path>. Do not edit this
>   file` (path per the layout ruling: repo/tools or macos/tools)
>   - `The next sync replaces it, and a manual change is lost`. During the
>     transition the detection (first 3 lines) also accepts `Synced from
>     bootstrap`, `Synced from repo-config` and `Generated by macos-setup`; a
>     later cleanup (with a `migrate.md` step) drops the old texts. Merge
>     sources carry `Merged by bootstrap: <path>` where the format has
>     comments; the engine does not read it.

> - Values row, item 1: the Mac values live in the `macos-setup` repo, made
>   private, at its root (not iCloud). The iCloud config folder never
>   existed (the `tools/` model is not live), so no data moves. A new Mac
>   runs `mise x gh@latest -- gh auth login` in `setup` before the clone. The
>   engine reads a folder of that clone; `MACOS_SETUP_CONFIG_PATH` stays the
>   way to point at it.

> - bootstrap layout (user, 2026-11-04): side folders at the root,
>   `repo/tools/<tool>/` and `macos/tools/<tool>/` (not `tools/repo/`), next
>   to `sync-engine/`. The header path becomes `repo/tools/<tool>/<path>` or
>   `macos/tools/<tool>/<path>`.

> - Clone URL: `https://github.com/virajp/bootstrap.git` on both sides
>   (public, fetch only, no SSH key needed on a new Mac). The normalized
>   origin compare stays as a guard for `SYNC_ENGINE_URL` in tests. The
>   engine never clones the private `macos-setup`: `setup` clones it once
>   after `gh auth login`; the engine reads the working clone at
>   `MACOS_SETUP_CONFIG_PATH`.

# Plan — The Mac front-end on the shared engine (2026-11-04)

## Goal

After this plan lands, `sync-engine/setup-sync` renders the Mac tools of
`macos/tools/` into `$HOME` on the shared libraries of `sync-engine/`. It reads
one values file, `macos.toml`, in the folder `MACOS_SETUP_CONFIG_PATH`. It
generates the mise config of each tool into
`~/.config/mise/conf.d/<tool>/mise.toml` and the user config into
`conf.d/zz-macos/mise.toml`. It keeps the stages, exit 4, the login shell
check, `mise bootstrap` and the symlink resolve of the old engine. It records
`bootstrap_commit` in `macos.toml`. `test:setup-sync` proves it with fixtures,
and the new orchestrator `test` runs every test task. The iCloud wait of the
old engine goes. No reversal of a standing decision.

Plan 9 of 16 — requires `2026-11-04-mise-generation-shared`; required by
`2026-11-04-macos-entry-tool`.

## Unit contract

Every unit prompt carries, in order: its ruling quoted from this plan, its
owned paths plus "touch nothing outside this list", the facts section, the
plan's shared files, and the return block below. A unit never bumps a version,
never runs a generator, never edits a doc, never adds a dependency the plan
does not list, never commits. A unit deletes with plain `rm`, never `git rm` —
it stages nothing. A unit never writes a lock file — the file a package
manager or a toolchain manager writes to pin what it resolved — with Write,
Edit, `sed` or a script: a lock file changes only as the output of the CLI
that owns it, the command the stack's package-manager conventions name, and
the unit keeps what that CLI wrote. A unit whose manifest change moves a lock
file lists that lock file in its `owns` beside the manifest.

A unit returns exactly this block and nothing else — no file contents, no diff:

    CHANGED: <path> — <one line>            (one per file)
    DECIDED: <what> — <why>                 (choices made inside scope, or none)
    DOCS FALSIFIED: <path> — <passage>      (reported, never edited; or none)
    GAP: <what the plan left unspecified and the assumption taken>   (or none)
    UNRESOLVED: <the ruling needed>         (or none)

A `GAP:` is a hole in the plan the unit could proceed past on a stated
assumption; it is recorded and the run continues. An `UNRESOLVED:` is a ruling
the unit could not proceed without; it blocks the unit and its dependents.

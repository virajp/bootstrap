## Ruling

From the design rulings of 2026-11-04:

> - bootstrap layout (user, 2026-11-04): side folders at the root,
>   `repo/tools/<tool>/` and `macos/tools/<tool>/` (not `tools/repo/`), next
>   to `sync-engine/`. The header path becomes `repo/tools/<tool>/<path>` or
>   `macos/tools/<tool>/<path>`.

> - One header on both sides, the repo form with the new path:
>   `Synced from bootstrap: <side>/tools/<tool>/<path>. Do not edit this
>   file` (path per the layout ruling: repo/tools or macos/tools)
>   - `The next sync replaces it, and a manual change is lost`. During the
>     transition the detection (first 3 lines) also accepts `Synced from
>     bootstrap`, `Synced from repo-config` and `Generated by macos-setup`; a
>     later cleanup (with a `migrate.md` step) drops the old texts. Merge
>     sources carry `Merged by bootstrap: <path>` where the format has
>     comments; the engine does not read it.

## Edits

1. **`sync-engine/repo-sync`** — near the top, define one root for the side,
   relative to the clone, for example `_RS_TOOLS_DIR=repo/tools`, and the
   packs file `_RS_PACKS_FILE=repo/packs.toml`. Replace each literal `tools/`
   that names a folder or a file of the clone with the variable: the tool
   folders, the `tools.toml` paths, the file list of a tool, the shared
   `.gitignore` of the `git` tool (`${_RS_TOOLS_DIR}/git/.gitignore`), the
   `find "$dir/tools"` of the template check, and the generated conf.d
   folder in the clone. Each message that names such a path uses the
   variable too (D7). A mise word such as `[tools]`, a values key such as
   `[tools.<name>]` and a consumer path stay.
2. **The generated header.** The header of each generated conf.d file is
   `# Synced from bootstrap: repo/tools/<tool>/tools.toml. Do not edit this
   file.`
   - `# The next sync replaces it, and a manual change is lost.` Build it from
     the variable and the header constant of `sync-engine/common`.
3. **`sync-engine/common`, `sync-engine/select`, `sync-engine/write`,
   `sync-engine/manifest`, `sync-engine/merge`, `sync-engine/clone`** — where
   one of them names `tools/` or `tools/packs.toml` of the clone, take the
   root or the packs file as a parameter or read the variable of the
   front-end; the library itself names no side. Keep the detection of the
   header texts unchanged (it accepts any `Synced from bootstrap` text).
   Update the comments of these files that name `tools/<tool>`.
